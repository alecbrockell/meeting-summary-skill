# Action items

Treat action items as execution records, not a recap of the meeting. Include only pending, sufficiently committed work.

## Choose one hierarchy

Use task- or workstream-first organization when the project structure controls, especially when a deliverable has multiple contributors:

```text
- Deliverable or workstream
  - Person: Complete the assigned contribution
  - Person: Complete the assigned contribution
  - Deadline: Supplied timing
```

Use person-first organization when several people have distinct assignments, especially when each person owns several tasks:

```text
- Person
  - Complete the first deliverable
  - Complete the second deliverable
    - Review: Supplied reviewer
```

Use one hierarchy consistently within the section and keep it to at most three compact levels: owner or workstream, action, then execution metadata. When one owner is implied, omit a redundant owner level and list tasks with any necessary subtasks. Follow a newer user-authored exemplar when it specifies another presentation.

## Write executable actions

- Begin each assignment with a concrete imperative verb
- Name the deliverable, decision, or other finish condition
- Keep one action per line where practical
- Nest only details that change execution
- Use `Support:`, `Review:`, and `Deadline:` only when the record supplies them
- Distinguish owners, contributors, and reviewers
- Preserve supplied mentions and links
- Use sentence case and no terminal periods

Place committed work without an owner under `Team / Unassigned`. If the meeting assigned no actions, write `No action items were assigned` rather than creating work.

## Reconcile and exclude

- Consolidate repeated discussion into the final agreed action
- Apply later corrections and remove completed, rejected, or superseded tasks
- Preserve material dependencies or unresolved conditions without presenting them as settled
- Convert an assignment to obtain a decision into a direct, answerable question when that is clearer
- Do not invent owners, deadlines, scope, review processes, controls, or written deliverables
- Exclude background, rationale, status recap, hedging, conversational residue, and procedural detail that belongs in a separate workplan or specification unless a brief detail changes execution

Use an underlined date-and-project workplan title when both are reliably available and the format supports it. In a combined response, place one underlined date-and-project title above the full response, then use the `Meeting summary` and `Action items` headings without repeating the title.
